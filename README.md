# U-Smile: Cardiac Patient Data Cleaning Pipeline

Reproducible data cleaning pipeline for the **U-Smile** project. The goal of this stage is strictly to **clean, standardize, and validate the cardiac patient dataset** before any exploratory data analysis or modeling begins.

---

## Project Structure

```text
u-smile_problem_classes/
├── data/
│   ├── raw/                    # Immutable raw data (NEVER edit manually)
│   │   ├── cardiac_patient_data.csv
│   │   └── cardiac_patient_data.xlsx
│   └── processed/              # Cleaned datasets generated by the pipeline
│       └── cardiac_patient_data_clean.csv
├── notebooks/
│   └── data_cleaning.ipynb     # Interactive exploration & prototyping
├── src/
│   ├── __init__.py
│   ├── clean_data.py           # Orchestrator: load, run ordered steps, save
│   └── cleaning_steps/         # Cleaning logic split by responsibility
│       ├── __init__.py
│       ├── text_normalization.py
│       ├── missing_values.py
│       └── date_formatting.py
├── .gitignore                  # Ignores .venv, caches, and intermediate files
├── README.md                   # Project documentation & team instructions
└── requirements.txt            # Dependencies (pandas, openpyxl, jupyter)

```

### Folder Roles

* **`data/raw/`**: Contains the original, unaltered data files (`.csv` and `.xlsx`). Treat this folder as read-only.
* **`data/processed/`**: Stores cleaned, standardized output produced by `src/clean_data.py`.
* **`notebooks/`**: For inspecting data, testing snippets, and prototyping cleaning functions.
* **`src/clean_data.py`**: Orchestrates loading, the ordered cleaning steps in `clean_data(df)`, and saving. Keep transformation logic in the step modules.
* **`src/cleaning_steps/`**: Contains the cleaning functions. Keep similar tasks in the same file. Add new files when needed.

## Running the Pipeline

To run the entire data cleaning pipeline from the command line:

```bash
python src/clean_data.py

```

### What happens when you run it:

1. Loads raw data from `data/raw/cardiac_patient_data.csv` (or `.xlsx`).
2. Runs the cleaning functions imported from `cleaning_steps/` in the explicit order defined by `clean_data()`.
3. Exports the clean dataset to `data/processed/cardiac_patient_data_clean.csv`.

## Missing-Value Imputation

`clean_missing_values()` runs after column pruning and conversion of dates to
day counts. This lets it fill missing day counts as well as other supported
columns. It uses MissForest-style imputation: it repeatedly trains
random forests on known values to predict missing ones. Existing values stay
unchanged. Numeric columns use regression; text, categories, booleans and binary
numeric columns use classification.

Change `max_iter`, `n_estimators`, and `random_state` in
`src/cleaning_steps/missing_values.py` to control runtime and repeatability.
Pass numeric category-code columns in `categorical_columns` and columns to
leave out in `exclude_columns` (by default, `cid` and `cid.1`). If pruning removes
a column listed in `categorical_columns`, the function warns and continues
without it. It does not recreate pruned columns.

Dates, entirely empty columns, columns containing infinity, and unsupported
values stay unchanged. Mostly numeric text, such as `ALDOpg/ml`, must be cleaned
and converted to numbers first. The function warns when missing values remain.
It does not treat strings such as `CHECK` as missing automatically. Numeric
predictions can be fractional, so counts may need a separate rounding rule.

This step can be slow on wide datasets. For later predictive modelling, split
the data first and fit imputation using training data only. This cleaning
function fits on all rows passed to it; it is not a reusable train/test imputer.

## Using in Jupyter Notebooks

If you want to prototype or inspect the data inside `notebooks/data_cleaning.ipynb`:

```python
import sys
from pathlib import Path

# Add project root to path if running inside notebooks/
sys.path.append(str(Path.cwd().parent))

from src.clean_data import load_data, clean_data, save_data

# 1. Load raw data
df = load_data()

# 2. Run current cleaning steps
cleaned_df = clean_data(df)

# 3. Save output
save_data(cleaned_df)

```

## Team Git Workflow

To keep our codebase stable and organized, we follow an Issue-Driven workflow.

1. **Create an Issue First:** Before writing code, open an issue. **Ensure the issue has a clear finish line** (e.g., "Impute missing age values" instead of "Look into missing data"). If an issue is too vague, break it down.
2. **Branch per Issue:** Create a dedicated feature branch for your issue branching directly off `main` (e.g., `feature/12-impute-age`).
3. **Merge via Pull Request:** Never push directly to `main`. When your work is done, open a Pull Request (PR) and have at least one team member review and approve it before merging.

Keep each issue focused on one task. Include the cleaning function and its
call in `clean_data.py` in the same PR. If two people need to edit the same file,
agree on who changes what. Before merging, update your branch from `main` and
run the pipeline again. If your work needs another PR, wait for that PR to merge first.

## Team Workflow: Adding Cleaning Steps

`src/clean_data.py` runs the pipeline: it loads the data, calls the cleaning
functions in order, and saves the result. Put cleaning logic in
`src/cleaning_steps/`.

1. **Create an issue and a branch from `main`.** Follow the Team Git Workflow above.
2. **Choose a file for your task.** The current files are:
   * `text_normalization.py`: Clean column names and text.
   * `missing_values.py`: Fill missing numeric and categorical values with iterative random forests (MissForest).
   * `date_formatting.py`: Fix dates and calculate observation time.

   Keep similar tasks together. You can add files such as `type_casting.py`
   for changing data types or `imputation.py` for filling missing values.
   These are examples, not files you must create now. You do not need a
   separate file for every function.

3. **Write a function that takes a DataFrame and returns a cleaned copy.**
   Keep loading and saving in `clean_data.py`. Explain which columns your
   function needs. Use this pattern:

   ```python
   def clean_something(df):
       df = df.copy()
       # Apply your cleaning rules here.
       return df
   ```

4. **Add the function to `src/clean_data.py`.** Add its import in both branches
   of the existing `if __package__` block, following the other imports.
   Then add `df = clean_something(df)` inside `clean_data(df)`.
   Put it after any steps it depends on and before the final
   `df.convert_dtypes()`. Keep the other steps in place.
5. **Run the pipeline from the project folder:**

   ```bash
   python src/clean_data.py
   ```

   Open `data/processed/cardiac_patient_data_clean.csv` and check the columns
   you changed. Check missing values and unusual inputs too. If you changed
   imports, also check that the notebook can still import the pipeline.
6. **Open a PR linked to your issue.** Explain what changed and how you checked
   it. Ask a teammate to review it before merging.

## Golden Rules for the Team

* **Do NOT modify raw data**: Never edit or overwrite files in `data/raw/`.
* **Reproducibility**: Any cleaning transformation must be implemented in Python code so anyone can reproduce the exact same output.
* **Main is Protected**: `main` must always be working. All changes must go through Issues, Feature Branches, and Pull Requests.
